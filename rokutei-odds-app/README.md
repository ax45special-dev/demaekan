# ROKUTEI オッズ収集(APK版)

公式サイト(boatrace.jp)の**締切時オッズ**(3連単・2連単・2連複)を、**間隔を空けて1件ずつ**取得して、スマホに貯めるアプリです。
取れたデータは、日ごとのCSVを**ZIPにまとめて共有**できます。

> **使う前に**: 公式サイトの利用条件(サイトポリシー)は「大量のアクセスなど、運営に支障を与える行為」を禁止しています。
> このアプリは、公式から許可をいただいた範囲(件数・間隔・時間帯)で使ってください。許可の条件を、必ず設定に反映してください。

## できること
- **取る日を決める**: 期間の中から**ランダムにN日**(月ごとに散らす)。あとから「さらにN日追加」もできます。
- **取った日・まだの日・取れていない日**を、画面で確認できます。**取れた日は、未取得リストから消えます。**
- 途中で止まっても(通信エラー・混雑・停止ボタン)、**取れていないレースだけ**を次回に再開します。
- **画面をつけたまま実行(確実)** と **裏で実行(画面OFFでもOK・要実機確認)** を選べます。
- 取れた日を**ZIPで共有**。共有できたのを確認してから、**端末のデータを削除**できます(取った記録は残ります)。

## 公式サイトへの配慮(あらかじめ入っている安全装置)
- **1件ずつ**取得(並列なし)。間隔は**3秒未満にできません**(初期値5秒、±20%のばらつき)。
- **混雑・拒否**(HTTP 403/429/503)が返ったら、**その場で止まります**(再試行しません)。
- 通信エラーが**5回続いたら**止まります。形式が変わって**読み取りに3回続けて失敗したら**止まります。
- **robots.txt** を読んで、禁止されていれば取りません。
- **今日以降の日は取りません**(確定前のオッズになるため)。**開催のない場・レースには、アクセスしません**(その日のレース一覧は、GitHub上の公開データから調べます)。
- 実行時間帯を限れます(例: 深夜1時〜7時)。1回の最大ページ数も決められます。
- 通信には、ブラウザを装わず、研究用の名前 `rokutei-lab-odds-research/1.0 (personal research)` を名乗ります。

## 取得する量の目安
- 1日(約150レース)= 3連単+2連単で**約300ページ**。5秒間隔で**約25分**。
- 30日分 = 約9,000ページ、約12.5時間。**1日1回、深夜に1日ずつ**取るのが、現実的です。

## 作り方(APK)
**方法A: GitHub Actions(Expoアカウント不要)**。リポジトリの `.github/workflows/rokutei-odds-apk.yml` が、このフォルダが変わるたびに(または Actions の画面から手動で)、テスト → `expo prebuild` → Gradle でAPKを作り、AndroidManifest の権限とサービスを検査して、`rokutei-odds-apk` という成果物にします。Actions の画面から、ダウンロードできます(デバッグ用の署名。自分のスマホに入れる用)。

**方法B: Expo の EAS Build**。Expo Goでは、裏で動く部分が使えません。
1. このフォルダを、GitHubの**非公開**リポジトリに入れる。
2. Expoのアカウントを作り、EAS Buildで `preview` プロファイルをビルドする(`eas.json` に、APK形式で設定済み)。
   `eas build -p android --profile preview` — このコマンドを動かす場所(パソコン/クラウドのClaude Code等)が必要です。
3. できたAPKをスマホに入れる(提供元不明のアプリの許可が必要)。

## 確認できていること / できていないこと
**ここ(開発環境)でテスト済み**(`npm test`、40個):
- 実物のオッズページ(3連単・2連単・2連複)から作った検証用ページの**読み取り**(欠場の艇、桁区切り、広告や偽の表が混ざったページ、空のセル・rowspanの両方)
- 取得の流れ全体(ランダム選択、再開、失敗の記録、諦め、時間帯、停止、robots.txt、今日以降を取らない、ZIP書き出しと削除)
- 『1レースだけ確認』、ログのファイル(`logs/run.log`、最大1MB)、ZIPの分割(N日ごと)、前回の途中経過の検出
- 同じ内容を、Python版(`odds_tool/`)でも作り、**同じ検証用ページで、同じ結果になる**ことを確認しています。

**実機でしか確認できていないこと(私は確認できていません)**:
1. **公式サイトの実際のHTML**で、読み取りが成功するか。実物の「表の中身」(文字)は確認済みですが、HTMLのタグの形は、検証用に推測で作ったものです。**最初に必ず、1レースだけで確認してください**(下記)。
2. **裏で実行**(フォアグラウンドサービス): ビルドが通るか、画面を消しても動き続けるか、通知が出るか。AndroidManifestへの追記(`plugins/withBackgroundActions.js`)は、ライブラリの案内に基づく設定ですが、実機でのビルドは試していません。
3. 画面(`App.js`)の見た目と操作。構文・importは確認済みですが、実際に動かしていません。

## 最初の確認手順(必ず、本番の前に)
0. 『1レースだけ確認』で、**2026-01-02 下関(19) 8R** を取る。3連単 120通り・1-3-2 が 6.8、2連単 30通り・1-3 が 3.8、2連複 15通り、逆数の合計が 1.2〜1.5 なら、読み取りは正しく動いています。
1. 『取る日を決める』で、**5日**だけ決める。『1回の最大ページ数』を **10** にする。
2. 『画面をつけたまま実行』を押す。10ページ(5レース分)で止まる。
3. ログと『状況』を見る。**読み取り失敗**が出ていなければ、読み取りは成功しています。
4. 一度『ZIPにして共有』し、CSVを開いて、**既知のレースと照合**する。
   例: **2026年1月2日 下関8R** は、3連単 **1-3-2 = 6.8倍**(払戻金680円で確認済み)。
5. 問題なければ、最大ページ数を戻し、『裏で実行』を試す。

もし読み取りに失敗した場合は、`work/raw_errors/` に、そのページの**生のHTML**が保存されます。それをClaude Codeに見せれば、パーサー(`src/core/parse.js`)を直せます。

## 読み取りの検査について(正直に)
読み取り結果は、必ず次の検査を通します。
- 通り数(3連単120・2連単30・2連複15)と、重複・欠けがないこと → **構造の読み違い(行・列のずれ、取り違え)は、確実に検出できます**。
- オッズの**逆数の合計が1.2〜1.5**(実物の表で1.336〜1.376)。

**限界(実測)**: 1つの組だけの桁違いは、この検査では**ほとんど検出できません**。実物の3連単120通りで調べると、10分の1への読み違いで検出できるのは**22通りだけ**(人気の組)、10倍への読み違いは**0通り**でした。
→ これを補うため、**集めたあとに、払戻金と照合する検査**(当たった組の締切時オッズ×100 = 払戻金)を、`TASKS.md` のタスク2で作ります。**データを分析に使う前に、必ず通してください。**

## 裏で実行がうまくいかない時
- ビルドが失敗する → `plugins/withBackgroundActions.js` を外し、『画面をつけたまま実行』だけで使う(充電しながら、画面をつけておく)。
- 起動してすぐ止まる/通知が出ない → 通知の許可(Android 13以降)、アプリの電池の最適化を『制限なし』にする。
- 画面を消すと止まる → 充電しながら使う(充電中は、端末が深い省電力に入りにくくなります)。

## 構成
- `src/core/` 取得の中身(パーサー、通信、状態、実行、ZIP)。画面に依存せず、Nodeでテストできる。
- `src/platform/` スマホ固有(ファイル保存、裏で動かす仕組み)。
- `App.js` 画面。
- `tests/` テスト(`npm test`)。`tests/fixtures/` は検証用ページ。
- `python-reference/` Python版(同じ動きの基準実装。PCで動かす時用)。
- `tools/` 集めたオッズを払戻金と照合する検査(`validate_against_payouts.py`)。
- `CLAUDE.md` / `TASKS.md` / `docs/KNOWLEDGE.md` Claude Code 向けの指示・やること・確認済みの事実。
