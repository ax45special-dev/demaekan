# CLAUDE.md — ROKUTEI オッズ収集アプリ

このファイルは、Claude Code が毎回最初に読む。**まず `TASKS.md`(やること)と `docs/KNOWLEDGE.md`(確認済みの事実)を読むこと。**

## これは何か
公式サイト(boatrace.jp)の**締切時オッズ**(3連単・2連単・2連複)を、**許可された範囲で、丁寧に**集めて、スマホに貯めるアプリ(Expo / React Native、Android APK)。
集めたデータは、利用者が ZIP で書き出して、別の場所(Claude のチャット)で分析する。**このリポジトリは「集める道具」だけ**で、分析や予想ロジックは含まない。

目的は研究: 「市場の価格(オッズ)」と「実際の勝つ確率」のズレがあるかを、**実際のオッズで**検証すること。
(これまでの1年分の払戻金だけでの検証では、外れた組のオッズが無く、決め手に欠けた。→ `docs/KNOWLEDGE.md` の「なぜオッズが要るか」)

## 役割分担(重要)
- **スマホのアプリ**が、公式サイトからオッズを取る(本番の取得は、利用者のスマホだけが行う)。
- **Claude Code(あなた)**は、コードを書く・テストする・APKをビルドする・実際のHTMLでパーサーを検証する。
  **公式サイトへのアクセスは、`TASKS.md` で許可した最小限(1レース=2ページ)だけ。ループや一括取得は、実行しない。**

## 絶対に守ること(破らない・弱めない)
1. **大量・並列・高速なアクセスにしない。** 公式のサイトポリシーは「不正アクセス、大量の情報送受信及び大量のアクセスなど、本サイトの運営に支障を与える行為」を禁止し、違反時は利用停止・損害賠償もありうる、としている。BOATCAST も同文言。
2. 次の安全装置を**弱めない・外さない**(テストで守られている):
   - 1件ずつ(並列なし)/ 間隔は設定値(初期5秒、±20%)で、**3秒未満には設定できない**(`MIN_INTERVAL`)。実際の待ちも、どんな設定でも2.4秒未満にならない。
   - **HTTP 403/429/503 が返ったら、再試行せずその場で止まる。**
   - 通信エラー連続5回、読み取り失敗(種類ごと)連続3回で、その回を止める。
   - robots.txt を読み、禁止なら取らない。
   - **今日以降の日は取らない**(確定前のオッズになる)。**開催のない場・レースにはアクセスしない**(その日のレース一覧は、GitHub上の公開データ=Boatrace Open API から調べる)。
3. **User-Agent でブラウザを装わない。** 研究用の名前 `rokutei-lab-odds-research/1.0 (personal research)` を名乗る。連絡先は入れない(利用者の判断、2026-10-07)。
4. **公式から得た許可の条件**(件数・間隔・時間帯)は、利用者から聞いて、設定の初期値に反映する。**条件を私は見ていない**(利用者が「問い合わせて大丈夫と返信が来た」と述べているだけ)。条件が分からない間は、保守的な初期値のままにして、利用者に確認する。
5. **BOATCAST(race.boatcast.jp)や個人サイト(orangebuoy.net)を、自動で取得しない。** BOATCAST は画面を動かす仕組みで、中身を確認できていない。orangebuoy は個人運営で、利用条件が不明。
6. **秘密情報(EXPO_TOKEN、パスワード等)を、コミットしない。** リポジトリは**非公開**。収集したデータも公開しない。

## 構成
```
App.js                    画面(操作と表示だけ)
src/core/*.js             取得の中身。画面に依存せず、Node でテストできる。ESM(src/core/package.json の type: module)
  parse.js                オッズページのHTMLの読み取り + 検査(120通り・重複なし・逆数の合計1.2〜1.5)
  net.js                  1件ずつ・間隔つきの取得、robots.txt、その日のレース一覧
  state.js                未取得/取得済み/取れていない日の管理(取れた日は未取得から消える)
  runner.js               1日分の取得→保存→状態更新(再開・停止・ページ数上限)
  storage.js / zip.js     日ごとのCSV保存 / ZIP(圧縮なし・自前)書き出し
  extras.js               1レースだけ確認・ログのファイル・ZIPの分割・前回の途中経過の検出
src/platform/*.js         スマホ固有(expo-file-system、react-native-background-actions)。★実機でしか確認できない
plugins/withBackgroundActions.js   AndroidManifest に権限とサービスを足す Expo 設定プラグイン ★未ビルド
tests/                    Node のテスト(npm test)。tests/fixtures/ は検証用ページ
python-reference/         Python 版(基準実装)。JS 版と同じ検証用ページで、同じ結果になること
tools/validate_against_payouts.py   集めたオッズを、払戻金と照合する事後検査(テスト: tools/test_validate.py)
docs/KNOWLEDGE.md         確認済みの事実・未確認の事項・研究の背景・落とし穴
```

## コマンド
- テスト: `npm test`(Node 22。**フォルダ指定の `node --test tests/` は動かない**。必ず npm test = ファイル指定)。現在 40 個すべて通る。
- Python 版: `cd python-reference && python3 -m unittest tests.test_parse tests.test_flow`(27個、すべて通る)。
- 注意: `src/core/package.json` の `{"type":"module"}` は、Node でテストするための仕掛け。消さない。import は `./xxx.js` と拡張子つきで書く。

## 変更する時のルール
- **パーサーを直したら、JS版とPython版の両方を直し、同じ検証用ページで同じ結果になることを確認する。**
- 読み取りの検査は**弱めない**。限界(単独の組の桁違いは、逆数の合計では、ほとんど検出できない=10分の1は22/120通り、10倍は0/120通りだけ検出)は `docs/KNOWLEDGE.md` に実測値がある。この限界は、**タスク2(払戻金との照合)で補う**ので、タスク2を省略しない。
- 実際のHTMLが検証用ページと違っていたら、**先に fixture を足してから**パーサーを直す(失敗するテストを先に作る)。
- テストを通すために、期待値を後から変えない。期待値は、実物の表(`docs/KNOWLEDGE.md`)から決める。意味のない書き方(`if False else` 等)で検証したふりをしない。
- 確認できていないことを、「できた」と書かない。**実機でしか確認できないことは、そう書く。**
